# 业务链路提取器

本模块在代码概览之后，把模块结构转换为适合经历包装和面试追问的端到端业务链路。

## 输入

- 项目根目录和用户指定范围
- 代码分析引擎的项目概览、技术栈、入口点和模块依赖

## 输出

- 新建当前版本的业务链路报告，并更新 `current_artifacts.business_chains`
- `evidence-manifest.json.business_chains`

## Step 1：选择入口策略

| 项目类型 | 入口到终点 |
|---|---|
| Spring Boot | Controller -> Service -> Repository/MQ/Client |
| Node.js Web | Route -> Handler -> Domain/Service -> Adapter |
| Go Web | Router -> Handler -> Use Case -> Repository |
| Python Web | Endpoint -> Application -> Data/External |
| CLI | Command -> Orchestrator -> Core -> IO Adapter |
| 前端 | User Action -> State -> Request -> Render |
| 数据/ML | Data Input -> Transform -> Model/Rule -> Evaluation/Output |
| 库/SDK | Public Interface -> Core -> Extension/IO |

找不到标准入口时，从公开接口、事件消费者、定时任务或 `main` 函数开始。

## Step 2：业务域分组

根据 URL/命令前缀、模块命名、数据实体和最终消费者分组。每个域标记：

- `BUSINESS`：直接形成用户或业务结果；
- `PLATFORM`：为多个业务域提供缓存、权限、消息、配置等能力；
- `TOOLING`：构建、开发工具或内部辅助；
- `MIXED`：不能可靠分类，需继续追踪。

不要把所有 CRUD 都归为低价值。若多个 CRUD 共同组成完整业务闭环，应作为一条链路评估。

## Step 3：追踪调用链

每条链路追踪到下列任一终点：

- 数据持久化；
- 消息发送或消费；
- 外部系统调用；
- 文件或报表输出；
- UI 状态更新；
- 模型推理或规则结果；
- 用户可观察结果。

默认追踪 3 层。出现动态分派、注册表、事件总线或接口注入时，继续定位具体实现；仍无法确定则标记 `[待确认]`，不得编造调用关系。

## Step 4：评估包装价值

每条链路按五项各打 0-2 分：

| 维度 | 0 | 1 | 2 |
|---|---|---|---|
| 闭环 | 孤立片段 | 部分闭环 | 输入到结果完整 |
| 业务影响 | 无消费者 | 内部使用 | 明确用户/业务消费者 |
| 技术决策 | 直接调用 | 有一项选择 | 有权衡、演进或约束 |
| 工程性 | 无异常处理 | 有基础保护 | 监控、容错、验证完整 |
| 可讲性 | 无法定位 | 能说流程 | 有冲突、取舍和结果 |

总分 `8-10` 为高优先，`5-7` 为中优先，`0-4` 为低优先。个人角色尚未确认时，价值评分仍可保留，但不能直接生成个人 Action。

## Step 5：生成增强候选

针对每条链路检查：

- 可观测性；
- 超时、重试、熔断和降级；
- 幂等、补偿和对账；
- 缓存一致性；
- 消息可靠性；
- 自动化测试；
- 性能验证；
- 灰度、回滚和配置开关；
- 权限和敏感数据处理。

缺失项只生成候选任务，不直接写成现有成果。

## business-chains.md 模板

```markdown
# 项目业务链路报告

## 业务域全景
| 业务域 | 类型 | 入口数 | 一句话说明 |
|---|---|---:|---|

## 核心链路

### CHAIN-001：{名称}
- 类型：{BUSINESS/PLATFORM/TOOLING/MIXED}
- 入口：`{入口}`
- 消费者：{最终用户或系统}
- 调用链：`{入口} -> {步骤} -> {终点}`
- 关键代码：`{路径}`
- 依赖：{数据库/缓存/MQ/外部系统}
- 当前工程能力：{已存在能力}
- 缺失能力：{可增强项}
- 包装价值：{高/中/低}（{分数}/10）
- 推荐追问：{问题}

## 价值节点排序
| 优先级 | 链路 | 节点 | 为什么值得讲 | 需要确认什么 |
|---|---|---|---|---|

## 增强候选
| 链路 | 缺口 | 推荐任务 | 验证方式 |
|---|---|---|---|
```

## 失败模式

| 触发条件 | 一线修复 | 仍失败则 |
|---|---|---|
| 无 Controller/Route | 搜索公开接口、消费者、定时任务、main | 降级为模块数据流 |
| 动态分派无法静态确定 | 查注册表、配置和实现列表 | 标记 `[待确认]` |
| 入口超过 30 个 | 先按业务域聚类 | 只详解价值最高的 10 条 |
| 项目没有业务消费者 | 按开发者/系统能力定义消费者 | 类型标为 `PLATFORM/TOOLING` |

## 不要做

- 不要逐行复述代码。
- 不要只列模块而不说明输入和最终消费者。
- 不要把猜测写成确定调用关系。
- 不要把缺失的工程能力写成已经实现。
- 不要限定为 Java 项目。
