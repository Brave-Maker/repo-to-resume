# 分层面试话术生成器

本模块把已完成拷打的声明转换为可伸缩回答结构。只消费 `GREEN/YELLOW` 声明；`RED/ORANGE` 只能生成训练稿，并在标题标注状态。

## 输入

- `DIRECT + SCRIPT_ONLY`：用户提供的简历要点、项目事实、目标岗位和可选学习材料
- `ARTIFACT/FULL_PIPELINE`：manifest 的当前简历、拷打报告、业务链路、学习路径和 `evidence-manifest.json`

## 输出

- `DIRECT + SCRIPT_ONLY`：在对话中交付分层话术，不创建文件或 manifest
- `ARTIFACT/FULL_PIPELINE`：新建当前版本话术，并更新 `current_artifacts.interview_scripts`

## 每条声明的四层结构

### 15 秒版本

一句话说清：业务问题 + 个人动作 + 结果。控制在 50 个汉字左右。

### 30 秒版本

使用三段：

1. 背景：谁遇到什么问题；
2. 动作：用户负责什么、采用什么方案；
3. 结果：数据、覆盖范围或工程闭环。

### 2 分钟版本

按以下顺序展开：

1. 背景与约束；
2. 用户角色；
3. 初始方案；
4. 初始方案的问题；
5. 最终方案；
6. A/B 方案取舍；
7. 验证方法和结果；
8. 失败边界与复盘。

使用口语短句，但不强制固定开场白。不要让所有回答都像同一套背诵模板。

### 深挖材料

每条声明附：

- 关键代码位置；
- 端到端数据流；
- 关键数据结构或接口；
- 两个替代方案；
- 两个失败场景；
- 数字来源或验证口径；
- 可以承认的不足；
- 不能前后矛盾的角色信息。

## 不同来源的表达策略

| 来源 | 话术重点 |
|---|---|
| `PERSONAL_FACT` | 个人决策、实现和结果 |
| `TEAM_FACT` | 团队目标 + 明确个人负责部分 |
| `MENTOR_DIRECTED` | 给定约束下的实现、调试和理解 |
| `SELF_PROJECT` | 自主选型、实现和验证 |
| `REPRODUCED` | 原项目能力、个人复现范围和新增改动 |
| `DESIGNED_ONLY` | 问题分析、方案对比和验证计划 |
| `NARRATIVE_FILL` | 完整工程推演、关键细节和风险问答 |

## 输出模板

```markdown
# {项目名} 面试话术

## 项目总述

### 15 秒
{一句话}

### 30 秒
{三段式}

## CLAIM-001：{简历 Bullet}

> 状态：{GREEN/YELLOW/TRAINING} | 来源：{source_type} | 风险：{risk}

### 15 秒回答
{内容}

### 30 秒回答
{内容}

### 2 分钟回答
{完整展开}

### 深挖备忘
- 关键代码：`{path}`
- 数据流：{链路}
- 方案对比：{A vs B}
- 失败场景：{场景 1}；{场景 2}
- 验证口径：{来源/环境/样本}
- 角色边界：{个人与团队}
- 当前不足：{可承认的限制}

### 高频追问
1. {问题 + 回答要点}
2. {问题 + 回答要点}
3. {问题 + 回答要点}
```

## 质量规则

- 15 秒、30 秒和 2 分钟版本必须信息一致；
- 不得在长版本新增简历和 manifest 中不存在的核心成果；
- 每条 2 分钟回答必须包含一个取舍和一个边界；
- 数字必须沿用 manifest 的口径；
- `YELLOW` 内容标注待补点；
- 高风险来源必须保留角色边界和验证口径。

## 失败模式

| 触发条件 | 一线修复 | 仍失败则 |
|---|---|---|
| 2 分钟版本没有方案演进 | 从拷打报告提取失败点和替代方案 | 标记“缺少演进”，转学习任务 |
| 三个版本事实不一致 | 以 manifest 为准重写 | 状态设为 `BLOCKED` |
| 内容过度书面 | 拆短句、删空话、保留因果 | 生成提纲而非逐字稿 |
| `RED` 声明被请求生成 | 只生成训练稿 | 标题标记 `NOT READY` |

## 不要做

- 不要强制所有回答使用同一句开场。
- 不要只给一版超长逐字稿。
- 不要隐藏来源和角色边界。
- 不要凭空补充新的数字或上线事实。
- 不要把训练稿标成可直接面试。
