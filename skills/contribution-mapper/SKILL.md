# Contribution Mapper

只回答“用户实际负责什么、证据是什么、哪些内容还不能归到用户”。本技能不生成简历正文，不把缺口自动转换为增强任务。

## 资源加载

1. 每次完整读取 [贡献映射器](../../references/contribution-mapper.md) 与 [声明政策](../../references/claim-policy.md)。
2. 需要压缩对话交付时只读取 [输出契约](../../references/output-contracts.md) 的“贡献映射”部分。
3. `ARTIFACT` 才读取 Manifest Schema，并只通过 `current_artifacts` 定位当前项目分析和业务链；`DIRECT` 不要求 manifest。

## 输入与边界

| 方式 | 最小输入 | 交付 |
|---|---|---|
| `DIRECT` | 一条候选链路、代码位置、现有要点或工作记录，加用户角色说明 | 对话中的归因表和证据缺口；不创建文件 |
| `ARTIFACT` | 有效 Manifest 及当前分析/业务链映射 | 版本化贡献映射并更新 `current_artifacts.contribution_map` |

缺少候选材料时只索取一条相关链路、代码位置或要点，不自动全仓分析。Git 只核对作者、时间、改动边界和演进顺序；提交体积不参与价值排序。

## 工作流

1. **锁定候选范围**：记录用户指定的链路、模块、要点数量和目标岗位。显式排除项是硬边界。
2. **分开项目事实与个人事实**：代码和测试说明系统实现了什么；用户口述、工单、评审与 Git 说明用户做了什么。两类证据不能互相替代。
3. **逐链路确认角色**：一次只问一个最高区分度问题，依次确认修改位置、方案决策者、调试过程、验证结果及只读部分。已有证据充分时不重复问。
4. **记录来源与掌握度**：按声明政策标记来源类型、`L0-L4`、证据和风险。证据不足时暂记 `L0（未核验）`，不得根据用户一句概述提升等级。冲突未解决时使用 `CODE_INFERRED/HIGH` 或 `BLOCKED`，不替用户选更有利版本。
5. **价值排序**：项目事实足以判断时，按业务/架构关键性、工程深度、方案取舍、结果/验证、岗位相关性和可追问深度各 `0-2` 分，保留 `candidate_value_score` 和理由。项目事实不足时价值分写 `N/A（待证据）`，不制造精确分数。角色门禁与价值分分开处理。
6. **分级候选**：输出 `READY / NEEDS_EVIDENCE / NEEDS_TRAINING / NEEDS_BUILD / BLOCKED`。同一功能的界面、接口、落库和文档默认合并，除非各自有独立决策和结果。
7. **交付并停止**：`DIRECT` 输出紧凑归因表；`ARTIFACT` 写版本文件和 Manifest 映射。只列可选补强方向，不生成增强任务或简历要点。

🔴 CHECKPOINT · ROLE & SOURCE

当项目事实与个人事实不足以确定角色，展示候选、当前角色、来源、证据和冲突后等待用户确认。用户允许自动处理不能替代个人角色事实；无法确认就保留风险并停止该候选。

## 输出要求

- 每个候选同时展示项目能力、用户角色、来源、代码/测试证据、归因证据、掌握度、价值分和当前状态；未核验项使用 `L0` 或 `N/A`，不留看似确定的空值；
- 明确哪些结论来自代码，哪些来自用户或 Git；
- 要求 N 条下游要点时比较至少 `max(6, 2N)` 个跨链路候选，材料不足则报告缺口；
- 实习项目只保留用户负责的高价值环节或一个核心闭环；开源项目不得把原作者实现记为用户原创。

## 失败与恢复

| 触发条件 | 一线修复 | 仍失败则 |
|---|---|---|
| 只有简历、没有代码 | 从要点反推所需证据并逐项询问 | 建立临时贡献图，个人归属标为高风险 |
| Git 历史缺失或作者不明 | 使用当前代码建立项目候选并询问个人范围 | 标记 `CODE_INFERRED/HIGH` |
| 用户称整个大型项目都由自己完成 | 按核心链路和代码位置逐项核对 | 未确认部分设为 `BLOCKED` |
| 用户不回答角色问题 | 保留项目事实，不提升个人归属 | 输出缺口并停止该候选 |
| `ARTIFACT` 映射缺失 | 报告缺失字段并要求修复 | 停止落盘，不猜文件名或最高版本 |
| 候选只来自一个大提交 | 回到用户授权的候选范围补充不同类别 | 标记候选池不完整，不输出最终排名 |

## 不要做

- 不要把模块职责表改名为个人贡献表。
- 不要从 commit 数、文件数、增删行数或文档数推断价值。
- 不要因价值高而放宽角色、来源、掌握度或风险门禁。
- 不要把实习项目的全产品或跨团队流程归给用户。
- 不要生成简历正文、增强任务、学习路径或模拟面试。
- 不要一次抛出长问卷或并行确认多个候选。

## 完成标准

每个候选都有项目事实与个人事实的分离记录、可定位证据、角色/来源/掌握度、价值分和准入状态；冲突未被静默解决；交付停在贡献映射阶段。
