# Experience Enhancer

把一个真实缺口变成 1-3 个有输入、动作、失败注入、验证和完成证据的任务。`DIRECT` 可从用户描述的当前能力或缺口独立开始；`ARTIFACT` 才承接已有业务链路与贡献映射。默认交付计划；计划不是已完成成果，也不会自动调用简历等下游技能。

## 资源加载

1. 每次完整读取 [经历增强实验室](../../references/experience-lab.md) 与 [声明政策](../../references/claim-policy.md)。
2. 需要压缩对话交付时读取 [输出契约](../../references/output-contracts.md) 的“经历增强”部分。
3. `ARTIFACT` 才读取 Manifest Schema 和当前业务链/贡献映射；`DIRECT` 使用用户给出的缺口上下文。

## 输入与边界

| 方式 | 最小输入 | 交付 |
|---|---|---|
| `DIRECT` | 当前能力或缺口、目标岗位/目标能力、可投入时间 | 对话中的任务卡；不创建文件，不修改项目 |
| `ARTIFACT` | 有效 Manifest 与当前链路/贡献映射 | 版本化增强计划并更新 `current_artifacts.enhancement_plan` |

完成模式必须明确标为 `IMPLEMENTED / REPRODUCED / DESIGNED / NARRATIVE_READY`。只有针对具体目标仓库、具体路径的独立写入授权才能选择 `IMPLEMENTED`；“全部做完”、自动确认或允许生成分析材料都不算源码修改授权。

## 工作流

1. **锁定缺口**：记录当前项目能力、目标岗位、可投入时间、运行条件和用户明确排除项。缺少上下文时只索取一个最关键缺口。
2. **选择 1-3 个方向**：优先核心链路、岗位高频、现有项目明显缺失且能形成验证闭环的能力。不要把监控、容错、缓存、测试、安全一次堆满。
3. **选择完成模式**：无写入授权时在 `REPRODUCED / DESIGNED / NARRATIVE_READY` 中选择；环境不可运行时从复现降级为设计，不把计划伪装成实现。
4. **生成任务卡**：每项包含对应链路、当前问题、方案选项与代价、执行步骤、至少一个失败注入、验证方法、完成证据和三类面试门禁。
5. **校验可执行性**：每一步必须有输入和输出，验收必须可观察。删除“优化性能”“增加监控”等没有对象和标准的空任务。
6. **估算成本与状态**：展示预计时间、前置条件、当前来源类型、完成后最高掌握度及仍需验证的风险；文档生成不能自动提升到 `L3/L4`。
7. **交付并停止**：`DIRECT` 输出任务卡；`ARTIFACT` 写计划并更新映射。除非已经通过代码修改检查点，否则不得实施任务。

🔴 CHECKPOINT · ENHANCEMENT PLAN

展示任务、完成模式、预计成本、验证方式和完成后可支持的候选事实。用户可以批准计划，但计划批准不等于源码写入授权。

🔴 CHECKPOINT · CODE MUTATION · STOP

首次修改目标项目代码前，必须展示目标仓库绝对路径、授权目录、预计文件、验证命令和回退方式，并等待针对这些路径的明确同意。未获得授权时立即降级到非写入模式，不创建、修改或删除目标仓库文件。

## 失败与恢复

| 触发条件 | 一线修复 | 仍失败则 |
|---|---|---|
| 项目无法运行 | 定位最小可复现模块 | 改为 `DESIGNED` 并标明验证范围 |
| 缺数据库或外部系统 | 使用 mock、内存替代或契约推演 | 保留未实测风险，不声称完成 |
| 用户时间不足 | 只保留最高价值的一项 | 使用 `NARRATIVE_READY`，风险保持高 |
| 任务完成但用户讲不清 | 回到链路、方案对比和失败边界 | 掌握度保持 `TRAINING_REQUIRED` |
| 未取得代码修改授权 | 保持目标仓库只读 | 输出设计/复现任务并停止 |
| 写入将越出授权范围 | 停止并展示越界路径 | 状态设为 `BLOCKED`，不继续写入 |
| `ARTIFACT` 映射损坏 | 按 Manifest 契约报告缺口 | 停止落盘，不猜最高版本 |

## 不要做

- 不要把任务计划、伪代码或设计文档写成已经上线的成果。
- 不要用“全部开始”替代目标项目代码修改授权。
- 不要在授权范围外创建、修改或删除文件。
- 不要一次堆满所有工程能力或生成无法验收的任务。
- 不要因无法实作就终止；应明确降级模式和风险。
- 不要自动生成简历、贡献映射、学习路径或面试材料。

## 完成标准

每个任务都有明确模式、对象、步骤、失败注入、验证、完成证据、成本和风险；未授权时目标仓库保持不变；交付停在增强计划阶段。
