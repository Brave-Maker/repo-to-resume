# Repo to Resume Orchestrator

本技能是多技能插件中的完整流程入口。根 `$repo-to-resume` 继续服务旧的单技能安装；插件安装使用 `$resume-pipeline` 编排完整流程，避免两个发现入口同名。

## 加载主契约

开始执行前完整读取 [根工作流](../../SKILL.md)。根工作流是完整流程、共享状态、授权边界和跨产物一致性的唯一事实源。

如果根工作流不存在或不可读，停止并报告插件安装不完整；不要凭本文件重建完整流程。

## 入口门禁

仅在以下任一条件成立时继续：

1. 用户明确要求“全部做完”“完整准备”或“端到端处理”；
2. 用户在同一次请求中明确组合两个及以上产物，例如“改简历并准备话术”；
3. 用户显式调用本技能并要求编排多个阶段。

单一请求必须交给对应子技能：

| 请求 | 子技能 |
|---|---|
| 项目架构与业务链分析 | `$project-analyzer` |
| 个人贡献与角色归因 | `$contribution-mapper` |
| 工程缺口与增强任务 | `$experience-enhancer` |
| 简历生成、改写与授权修订 | `$resume-writer` |
| 单条声明压力验证 | `$claim-grill` |
| 学习路径与交互学习页 | `$project-learning` |
| 分层面试话术 | `$interview-script` |
| 一次一题模拟面试 | `$mock-interview` |
| 只读简历/材料质量审查 | `$resume-auditor` |

只有组合多个子任务或明确完整流程时由本技能编排。根工作流继续作为共享状态与跨阶段授权的唯一事实源。

🔴 CHECKPOINT · MODE & SCOPE

按根工作流展示本次阶段、停止点、预计产物和授权边界。组合范围或完整流程必须等待确认；确认不代表允许修改目标项目源码。

## 失败分支

| 触发条件 | 一线处理 | 仍失败则 |
|---|---|---|
| 请求只有一个明确产物 | 路由到上表对应子技能 | 无法匹配时只问一个范围问题，不以根流程兜底扩张 |
| 用户范围含糊 | 只问一个区分度最高的范围问题 | 未回答则停止，不默认完整流程 |
| 根工作流不可读 | 报告缺失的绝对路径 | 停止，不生成部分产物 |

## 不要做

- 不要因为项目路径、Git URL 或“完整项目经历”而自动启动完整流程。
- 不要把插件能力清单当作本次待办清单。
- 不要让组合授权替代项目来源、简历写回或源码修改授权。
- 不要复制根工作流中的阶段规则到本文件。
