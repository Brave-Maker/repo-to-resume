# Claim Grill

验证用户已经提供的简历声明能否经受项目面试追问。本技能只发现和分级漏洞，不负责润色简历，也不自动执行修复、学习或模拟面试。

## 资源加载

1. 每次都完整读取 [拷打门禁](../../references/claim-grill.md)。
2. 需要生成报告或对话摘要时，读取 [输出契约](../../references/output-contracts.md) 的“拷打”部分。
3. 仅在用户明确要求接入现有多阶段材料时读取 `evidence-manifest.json`；通过 `current_artifacts` 定位当前简历和证据，不猜测固定文件名或最高 `-vN`。

## 输入与边界

支持两种执行方式：

| 方式 | 最小输入 | 输出 |
|---|---|---|
| `DIRECT` | 用户提供的一条或多条简历要点 | 对话式逐层追问与单条结论 |
| `ARTIFACT` | 有效 manifest 及其当前简历映射 | 版本化拷打报告；更新由完整流程负责 |

`DIRECT` 不要求项目来源、全仓扫描或 manifest。用户没有提供待拷打内容时，只索取一条简历要点；不要自动分析仓库或生成候选声明。

## 工作流

1. **锁定声明**：保留原文，标识其中的角色、数字、因果和技术实现等高风险片段。多条声明按用户顺序逐条处理，不并行发问。
2. **选择问题**：按事实、个人角色、技术实现、方案对比、数据与验证、边界与复盘六层推进；已有材料已经充分回答某层时记录证据，不重复提问。
3. **一次一问**：每轮只输出一个问题，然后等待用户实际回答。不要同时附带下一问、参考答案或改写版本。
4. **回答核验**：将回答与用户材料、代码或 manifest 证据比对。只有实际回答或可定位证据才能提升等级；不能用常见实现替用户补事实。
5. **分层评级**：每层使用 `RED / ORANGE / YELLOW / GREEN`，单条最终等级取最差层，不取平均值。用户答不上来时先给一次定位提示，仍无法说明则记录对应漏洞。
6. **完成单条**：六层结束后展示最终等级、最大漏洞和一个明确修复动作。用户要求多条时，再进入下一条。

🔴 CHECKPOINT · CLAIM RESULT

单条完成后展示证据、等级和最大漏洞。存在 `RED` 时停止向面试话术或模拟面试推进；本技能只说明应回到贡献确认、经历增强、简历修订或学习中的哪一类动作，不自动执行。

## 高风险门禁

声明含无口径数字、全局主导、从零到一、百万级规模，或来源为 `BORROWED_CONTEXT / NARRATIVE_FILL` 时，必须完成全部六层。未获得用户实际回答时可以做显式标注的干跑预审，但不得声称通过、不得生成面试得分。

## 失败与恢复

| 触发条件 | 一线修复 | 仍失败则 |
|---|---|---|
| 用户没有提供声明 | 只索取一条待拷打要点 | 停止，不生成示例声明 |
| 用户不回答当前问题 | 给一个代码位置或证据口径提示 | 记录 `RED: no evidence` 并结束该层 |
| 声明没有数字 | 改查覆盖范围、正确性或故障场景 | 不强行编造指标 |
| 代码不可访问 | 使用用户提供的架构、伪代码和场景解释 | 技术实现层最高暂评 `YELLOW` |
| manifest 映射缺失或文件不存在 | 报告缺失映射并要求修复 | 停止 `ARTIFACT` 执行，不猜文件名 |
| 回答与现有证据冲突 | 并列展示冲突并只问用户确认哪项真实 | 未解决则标记 `BLOCKED` |

## 输出要求

- 进行中的轮次只显示当前声明、当前层和一个问题。
- 单条完成后显示六层摘要、最终等级、最大漏洞和一个修复动作。
- 只有用户要求报告或处于已确认的多阶段流程时，才使用 `claim-grill-report.md` 模板落盘。
- 中文输出使用“简历要点、声明、检查点”等自然中文；内部等级首次出现时附中文含义。

## 不要做

- 不要一次抛出六个问题或一次拷打多条声明。
- 不要在验证完成前润色、重写或删除原声明。
- 不要替用户回答后再判定其已经掌握。
- 不要用总分掩盖事实归属、数字口径或技术实现中的 `RED`。
- 不要只考通用八股而不追问当前项目的入口、链路和证据。
- 不要完成拷打后自动进入学习、话术或模拟面试。

## 完成标准

当前声明的六层均有用户回答、可定位证据或明确缺口；最终等级采用最差层；风险与唯一优先修复动作已经展示；流程停在用户要求的声明范围内。
