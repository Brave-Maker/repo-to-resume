# Interview Script

把同一事实压缩成不同时间长度的可说答案。话术只能扩展解释深度，不能改变项目背景、个人角色、技术方案或结果口径。

## 资源加载

1. 每次完整读取 [分层话术生成器](../../references/interview-script-generator.md)。
2. 涉及来源或高风险数字时读取 [声明政策](../../references/claim-policy.md)。
3. 需要摘要时读取 [输出契约](../../references/output-contracts.md) 的“学习与话术”部分。
4. `ARTIFACT` 才读取 Manifest Schema，并通过 `current_artifacts` 获取当前简历、链路和学习路径；`DIRECT` 使用用户当前材料。

## 输入与边界

| 方式 | 最小输入 | 交付 |
|---|---|---|
| `DIRECT` | 一条或多条简历要点/项目事实、目标岗位 | 对话中的分层话术；不创建文件 |
| `ARTIFACT` | 有效 Manifest 及当前简历/证据映射 | 版本化话术并更新 `current_artifacts.interview_scripts` |

缺少项目事实时只索取一条要点或项目摘要。只生成话术，不现场扮演面试官、不等待用户逐题回答、不产生面试得分。

## 工作流

1. **锁定声明与事实**：保留原要点，提取业务问题、个人角色、技术行动、结果口径、方案权衡和失败边界。冲突事实并列展示，不自行选择。
2. **生成项目总述**：15 秒只讲定位、个人范围和最强结果；30 秒补核心链路与技术选择。不能把团队项目改成个人端到端主导。
3. **生成单条四层话术**：15 秒给结论；30 秒补问题、任务和行动；2 分钟完整讲情境、决策、实现、验证、结果和边界；深挖材料列代码位置、替代方案、失败路径和口径。
4. **生成高频追问**：每条绑定当前声明，覆盖为什么这样选、如何实现、如何验证、失败会怎样、用户实际负责什么。给答题线索，不替用户虚构经历。
5. **一致性检查**：四种长度必须使用同一背景、角色、方案和数字；长版本只能增加细节，不能制造新事实。`RED/BLOCKED` 内容不得包装成可直接使用话术。
6. **按方式交付并停止**：`DIRECT` 对话输出；`ARTIFACT` 写版本文件和映射。完成后不进入模拟面试、评分、学习或简历改写。

🔴 CHECKPOINT · SCRIPT FACTS

当要点中的角色、数字或因果缺少依据时，展示唯一最高风险事实并只问一个问题。无法确认则保留 `[待确认]`，对应话术标为训练稿，不用流畅表达掩盖风险。

## 失败与恢复

| 触发条件 | 一线修复 | 仍失败则 |
|---|---|---|
| 没有要点或项目事实 | 只索取一条简历要点或项目摘要 | 停止，不生成通用模板冒充项目话术 |
| 声明含无口径数字 | 改写为待确认口径并追问一次 | 移除数字，话术标训练稿 |
| 个人角色冲突 | 并列团队与个人范围并追问 | 使用更保守范围并标 `[待确认]` |
| 2 分钟版本出现新事实 | 删除新增事实并从已确认材料重建 | 标记该段不可使用 |
| 高风险声明未通过拷打 | 保留为训练话术并列风险 | 不生成“可直接面试”结论 |
| `ARTIFACT` 映射缺失 | 报告缺失映射 | 停止，不猜最高版本 |

## 不要做

- 不要让 15 秒、30 秒和 2 分钟版本讲成不同事实。
- 不要用更强动词、美化背景或补充常见实现来让话术更顺。
- 不要把无口径数字、高风险来源或团队成果静默降风险。
- 不要只给泛用八股，不绑定当前项目与代码证据。
- 不要现场逐题提问、模拟用户回答或生成面试得分。
- 不要自动改写简历、生成学习路径或启动模拟面试。

## 完成标准

每条声明具备四层一致话术、方案取舍、失败边界和具体追问；所有事实可追溯，风险显式保留；流程停在话术交付。
