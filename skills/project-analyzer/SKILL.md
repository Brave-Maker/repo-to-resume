# Project Analyzer

只回答“这个项目实现了什么、怎样运行、数据如何流动、证据在哪里”。本技能不判断用户个人做了什么，不生成简历内容，也不自动进入贡献映射、学习或面试阶段。

## 资源加载

1. 每次完整读取 [代码分析引擎](../../references/code-analysis-engine.md)。
2. 需要追踪业务结果时完整读取 [业务链路提取器](../../references/business-chain-extractor.md)，只执行其中的 `ANALYZE_ONLY` 分支。项目是纯库、工具或基础设施时仍定义开发者或下游系统消费者，不强行虚构业务用户。
3. 需要在对话中压缩展示时读取 [输出契约](../../references/output-contracts.md) 的“项目分析”部分。
4. 仅在已确认的多阶段材料中读取 Manifest Schema，并通过 `current_artifacts` 更新当前产物；单步骤分析不要求也不初始化 manifest。

## 输入与停止边界

| 方式 | 最小输入 | 交付 |
|---|---|---|
| `DIRECT` | 本地路径、Git URL、压缩包或代码片段 | 对话中的项目分析与业务链路摘要，不创建持久化产物或 manifest |
| `ARTIFACT` | 已确认的多阶段材料及有效 Manifest | 版本化 `project-analysis.md`、`business-chains.md` 和更新后的 `current_artifacts` |

用户给出“只分析 `src/`”“跳过测试/vendor”等范围时视为硬边界。缺少项目材料时只索取一个路径、URL 或代码包，不要求项目来源、目标岗位或简历。

目标仓库默认只读。分析授权不等于修改源码、补测试、创建索引或执行迁移。`DIRECT` 不修改工作区；Git URL 如需检出，只能使用系统临时目录并在交付前清理，不把临时副本当作用户产物。

## 工作流

1. **解析目标与范围**：解析绝对路径或仓库 URL，记录包含目录、排除目录、语言或目标链路。先确认目标真实存在且可读；不要扫描范围外的相邻目录。
2. **选择定位方式**：仓库根存在 `.codegraph/` 时，先用 CodeGraph 查询符号、入口和调用路径，再读取关键文件验证；不存在时使用 `rg`、构建文件和语言工具链。不要为了分析而创建 `.codegraph/`。
3. **建立授权范围概览**：识别范围内的产品用途、技术栈、构建方式、顶层模块、公开入口、测试和基础设施。用户授权整个仓库时覆盖全仓；用户限定目录时只读取该目录，范围外的上下游只能标记为 `[待确认]`。需要越界验证时先经过检查点，不能把“理解上下游”当作隐含授权。
4. **选择分析深度**：小型仓库做文件级覆盖；中大型仓库先模块级覆盖，再深挖分属不同类别的 2-3 条高价值链路。明确列出未深挖范围，不用无限扫描换取表面完整。
5. **追踪端到端链路**：从路由、命令、消费者、定时任务或公开 API 出发，追到持久化、消息、外部系统、文件、UI、模型结果或其他可观察终点。记录入口、步骤、消费者、关键代码、依赖和失败边界。
6. **建立证据与不确定项**：每项重要判断至少给出文件路径与符号或配置位置。动态分派、依赖注入或事件路由无法确认时标记 `[待确认]`；不要根据名称补齐调用关系。
7. **形成价值节点**：覆盖核心业务、架构扩展、可靠性/性能、安全、测试与交付中仓库实际存在的类别。这里只评价项目节点，不声明个人归属，不把 Git 规模当价值证据。
8. **按方式交付并停止**：`DIRECT` 在对话中输出；`ARTIFACT` 才写版本化文件和更新 Manifest。完成分析后停止，不生成简历、贡献映射、增强任务、学习页面或面试材料。

🔴 CHECKPOINT · ANALYSIS SCOPE

仅在需要超出用户指定目录、下载额外私有材料、运行高成本构建，或从 `DIRECT` 切换为已有多阶段材料中的 `ARTIFACT` 时展示新增范围、原因和预计产物并等待确认。没有有效 Manifest 时保持 `DIRECT`，不为单步骤分析自行初始化。用户边界已经明确且保持只读时直接执行，不重复确认。

## 输出要求

至少包含：

- 一句话产品定位与实际技术栈；
- 核心模块及系统职责；
- 1-3 条端到端链路，包含入口、关键步骤和最终消费者；
- 关键技术决策、已存在的工程能力与缺口；
- 代码证据、授权范围内可用的测试证据和 `[待确认]` 关系；
- 扫描范围、跳过范围和分析完整性说明。

`DIRECT` 输出使用紧凑表格和链路列表，不把内部 JSON、全量目录树或逐文件笔记倾倒给用户。用户只问一个模块时，只使用授权范围内足以说明其上下游的最小上下文。

## 失败与恢复

| 触发条件 | 一线修复 | 仍失败则 |
|---|---|---|
| 路径不存在或不可读 | 展示解析后的绝对路径并重新核对一次 | 只索取一个有效路径、URL 或代码包后停止 |
| Git URL 克隆失败 | 检查 URL、网络和现有凭据 | 请求本地路径或压缩包，不猜仓库内容 |
| 仓库过大或分析超时 | 从文件级降为模块级，再聚焦 2-3 条关键链路 | 输出轻量概览并标记“深度分析不完整” |
| 没有标准 Controller/Route | 搜索公开接口、消费者、任务、命令或 `main` | 输出模块数据流并说明未找到外部入口 |
| 动态调用无法静态确认 | 查注册表、配置、实现列表和相关测试 | 标记 `[待确认]`，不写成确定关系 |
| 测试或构建无法运行 | 继续静态分析，并读取已有测试验证意图 | 明确标记“未完成运行验证” |
| 文件可能包含密钥或凭据 | 只记录文件名和配置作用，不读取值 | 跳过内容并记录扫描限制 |
| `ARTIFACT` 映射缺失或损坏 | 按 Manifest 契约修复当前映射 | 未确认修复前停止落盘，不猜最高版本 |

## 不要做

- 不要把系统模块职责写成用户个人贡献。
- 不要生成、示范或改写简历要点。
- 不要因发现亮点而自动进入贡献确认、经历增强或学习路径。
- 不要用 README、目录名或依赖声明替代当前代码证据。
- 不要读取或展示密钥、token、密码和私有配置值。
- 不要把动态分派、消息消费者或接口实现的猜测写成确定调用链。
- 不要从 commit 数、文件数、增删行数或文档数量推断项目价值。
- 不要修改目标源码、补测试或创建 CodeGraph 索引。

## 完成标准

用户指定范围已覆盖；核心模块和至少一条可观察链路有代码证据；无法确认的关系已显式标记；输出说明扫描与验证限制；未生成范围外产物，并在项目分析阶段停止。
